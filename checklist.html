Test Checklists

Reusable checklists I consolidated from my testing projects — a quick roadmap before diving into formal test cases.

Checklist — Web form

Text fields

  • Name field accepts letters only (rejects numbers and special characters)
  • E-mail field requires a valid format with domain (name@domain.com)
  • E-mail field rejects spaces and text without @
  • Phone field accepts digits only
  • Phone field enforces the country's digit count (BR/US)
  • Numeric fields (weight, height, date) reject letters and special characters
  • Character-limited fields enforce the maximum (e.g., 255)
  • Boundary values tested (min−1, min, max, max+1)

Validation & submission

  • Form is not submitted with every field empty
  • Form is not submitted with only one field filled
  • Clear error message for each empty required field
  • Success message displayed after a valid submission
  • Duplicate registration shows a failure message
  • Password meets minimum requirements (8+ characters, letters, numbers, specials)
  • Mismatched password confirmation shows an error

Navigation & usability

  • Every button responds to clicks (no "dead" buttons)
  • Menu links and sublinks load the correct pages
  • Back/forward between pages preserves entered data
  • Readable text (adequate contrast against the background)
  • Consistent language across all screens and buttons
  • Explicit measurement units (hours/days, kg/lb)
  • Mutually exclusive options cannot be checked together
  • Choices can be undone

Cross-browser / devices

  • Google Chrome
  • Mozilla Firefox
  • Microsoft Edge
  • Safari
  • iOS (responsive layout)
  • Android (responsive layout)

Checklist — Mobile app

Installation

  • Install from the official store (App Store / Google Play) successfully
  • Interrupting the install leaves no partially installed app
  • Uninstall and reinstall works with full integrity

Device resources

  • Front and rear cameras work within the app's features
  • Permissions requested at the right moment (camera, location, notifications)
  • App works after denying and later granting a permission
  • GPS: correct behavior with location on/off

Interruptions

  • Incoming phone call answered and ended: entered data persists
  • SMS/notification read and return to the app: state preserved
  • Banner notifications appear while the app is in the background

Device conditions

  • High (80%), medium (49%), and critical (9%) battery: app remains functional
  • Different screen resolutions (phone, tablet, 1080p+)
  • Portrait/landscape orientation
  • Connectivity: WiFi, mobile data, and switching between networks
  • Device language changed: app follows it or offers a manual switch
