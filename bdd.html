BDD Scenarios with Test Design Techniques

Functional scenarios written in Gherkin (Given/When/Then) for the "Crowdtest" app, tagging each scenario with the test design technique used — equivalence partitioning, boundary value analysis, state transition, or decision table.

User story: As a Crowdtest app user, I want to register new issue reports, so that they can be reviewed and tested by the community.

Feature: Issue registration

Scenario 01 @equivalence-partitioning

Feature: Issue registration
Technique: Equivalence Partitioning

Scenario: Register an issue with valid data
  Given I am on the issue registration page
  When I fill in every required field correctly
  And I click the register button
  Then a confirmation message should appear
  And the issue is added to the issue list

Scenario 02 @equivalence-partitioning

Scenario: Register an issue with invalid data
  Given I am on the issue registration page
  When I do not fill in every required field
  And I click the register button
  Then a message should ask me to review the required fields
       before the issue can be submitted

Scenario 03 @boundary-value

Scenario: Register video and photo evidence
  Given I am on the issue registration page
  And I fill in every required field
  When I attach the project evidence
  And I click the register button
  Then a confirmation message should require at least
       one video and one photo for the registration
  And the issue is added to the issue list

Why tag the technique?

  • Equivalence partitioning — splits inputs into valid and invalid classes; one representative per class covers the behavior.
  • Boundary value analysis — tests the edges (minimums and maximums), where most defects live.
  • Tagging the technique on the scenario documents the coverage intent and makes team review easier.
